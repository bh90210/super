# Frontend upstream provenance

`frontend/` is a fork of **[francoborrelli/spotify-react-web-client](https://github.com/francoborrelli/spotify-react-web-client)**
(MIT licensed — see `LICENSE`). It is the Spotify UI shell for `super`; the Go
backend owns all data.

Do **not** use [francoborrelli/portfolio](https://github.com/francoborrelli/portfolio)
as a source: it is GPL-3.0 (copyleft) and only ships 5 screens, so it is both a
licensing trap and a smaller starting point.

The sync commit is a merge whose second parent is the **raw upstream commit**.
That ancestor is what makes `git subtree pull` work, so do not rebase or
squash it away.

## Pulling future upstream changes

```bash
git fetch frontend-upstream main
git subtree pull --prefix=frontend frontend-upstream main
```

Subsequent pulls only carry the delta since the last split, so they are small.
Because the same commit is merged at the root, the merge pull at the end is
always a harmless no-op.

## Local divergence to preserve

These carry the Wails/Go integration and must survive every upstream pull. If a
pull conflicts, keep our side here.

- `src/store/slices/auth.ts` — Spotify auth disabled; `mockUser` provides the
  identity so every screen renders without a Premium account.
- `src/axios.ts` — Spotify transport replaced with a local mock. It answers the
  whole `/v1` surface (browse, me, search, playlists, albums, artists, shows,
  episodes) with empty collections.
- `src/App.tsx` — `ErrorBoundary` replaces the auth/Web Playback SDK gate;
  auth-gated route filtering and the playback key/contextmenu handlers removed.
- `src/utils/spotify/login.ts` — placeholder `VITE_SPOTIFY_*` values.
- `src/constants/spotify.ts` — images referenced with plain `/images/...` paths.
- Wails glue (not from upstream): `index.html` at the frontend root,
  `vite.config.ts`, `@wailsio/runtime` in `package.json` (currently
  `3.0.0-beta.20`), the `build:dev`/`build` scripts, and `.npmrc`
  (`legacy-peer-deps` for `react-player-controls`). `bindings/` is generated by
  Wails — regenerate with `wails3 generate bindings -clean=true -ts` after any
  Go service signature change, and keep the runtime version in step with the
  `github.com/wailsapp/wails/v3` version in `go.mod`.

## Upstream work we do NOT want

Upstream invested heavily in surviving Spotify's Feb-2026 rate limits against
the real API. That work is meaningless here and should be dropped on conflict:

- the Feb-2026 Spotify Web API migration (`8b112d8`)
- the RTK Query / IndexedDB caching layer and request fan-out tuning
  (`4c7dbb8`, `c2387dd`, `c1ed1e9`, `299c094`, `6f16b09`)
- 429 backoff, PKCE hardening, Web Playback SDK lifecycle
  (`325dd3f`, `733de13`, `20e8cdb`)
- the upstream Vite migration (`c48ed78`) — we keep our own Wails-aware config

The RTK Query files (`src/store/api.ts`, `src/store/endpoints/*`) and the
podcast screens are fine to keep: they sit on top of `src/axios.ts`, so they
work unchanged against the mock and later against the Go bindings.
